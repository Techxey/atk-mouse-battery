# 协议说明（ATK / Compx 2.4G 鼠标）

本文记录本项目使用的私有 HID 协议，供移植、调试和适配新设备参考。所有报文都是在 **ATK U2 PLUS（NK 版）**
2.4G 接收器（`VID 0x373B / PID 0x10C9`）上实测得到的。

## 设备

| 用途 | Instance | 说明 |
|---|---|---|
| 2.4G 接收器 | `USB\VID_373B&PID_10C9` | 产品字符串 `NK mouse NANO dongle`，厂商 `Compx` |
| 有线模式 | `USB\VID_373B&PID_126C` | 产品字符串 `ATK U2 PLUS NK` |

接收器对外暴露 3 个 HID 接口，其中与本协议相关的是：

| 顶层集合 | usagePage / usage | in / out | 说明 |
|---|---|---|---|
| `MI_01 Col04` | `0xFF02 / 0x0002` | 20 / 20 | 预留（未使用） |
| `MI_01 Col05` | `0xFF02 / 0x0002` | **17 / 17** | **命令通道：查询与响应** |
| `MI_01 Col06` | `0xFF04 / 0x0002` | feature 8 | 报告 ID `6`，会镜像最近一帧数据（未使用） |

（相同接收器还会枚举键盘/消费控制/鼠标等标准集合，与电量无关。）

## 帧格式

17 字节 = **报告 ID（1 字节）+ 载荷（16 字节）**。

- 报告 ID：`0x08`
- 载荷：`payload[0]` 为操作码（opcode），后 14 字节为参数，`payload[15]` 为校验字节
- **校验规则：16 字节载荷之和的低 8 位等于 `0x4D`**

```
checksum = (0x4D - (sum(payload[0..14]) & 0xFF)) & 0xFF
```

## 查询电量

发送（17 字节）：

```
08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
```

校验：`0x04 + 0x49 = 0x4D`。

接收（实测）：

```
08 04 00 00 00 02 2D 00 0E 67 00 00 00 00 00 00 A5
```

解析：

| 字段 | 偏移（含报告 ID） | 值示例 | 含义 |
|---|---|---|---|
| opcode | `[1]` | `0x04` | 电量响应 |
| — | `[5]` | `0x02` | 固定/状态位（含义未确认） |
| 电量 | `[6]` | `0x2D` = 45 | 电量百分比（0–100） |
| — | `[7]` | `0x00` | 电压高字节 |
| 电压 | `[8..9]` | `0x0E67` = 3687 | 电压 mV（大端） |
| 校验 | `[16]` | `0xA5` | 载荷和低 8 位 = 0x4D |

> 45% / 3679–3687 mV 与 ATK 网页驱动 `https://hub.atk.pro` 的显示值一致。

## 其他观察到的帧（同一通道）

接收器会周期性（约 30–40 秒）或随鼠标活动推送其他 opcode 的帧，例如：

```
08 1C 00 00 00 01 00 00 00 00 00 00 00 00 00 00 30     # 心跳/链路状态
08 1C 00 00 00 01 01 00 00 00 00 00 00 00 00 00 2F
08 03 00 00 00 01 01 00 00 00 00 00 00 00 00 00 48
08 0E 00 00 00 01 00 00 00 00 00 00 00 00 00 00 3E
```

这些帧同样满足"载荷和 = `0x4D`"的校验；本项目只解析 `opcode == 0x04` 的响应，其余忽略。
它们可用于判断"接收器有数据来往"，但不能替代电量查询。

## 调试方法

1. 用本项目自带的探测模式确认协议：

   ```bat
   MouseBattery.exe --probe
   type %TEMP%\atk-probe.txt
   ```

2. 若需抓取新设备的报文，可在 Windows 上用 Wireshark + USBPcap 捕获 USB 流量，或写一个直接调用
   `HidD_GetFeature` / `ReadFile` 的小程序，边操作官方驱动边记录：
   - 打开 `usagePage=0xFF02` 且长度 17 的集合
   - 对照官方驱动"查看电量"时刻的收发数据，定位查询帧与响应字段

3. 注意：**不要盲目向未知设备写入非查询报文**，部分 opcode 可能修改设备配置或触发恢复模式。

## 兼容性提示

- 不同型号/代际的 ATK 设备可能使用不同的 usage page（如 `0xFF04`）、不同的报告 ID 或不同的 opcode；
  适配前先用上面的方法确认，再改 `src/main.c` 顶部常量。
- 本协议为社区逆向整理，非官方文档，可能随固件升级变化。
